# RGB＋热红外目标检测：研一到研二上研究工作区

创建日期：2026-11-02。目标：2027-07-31 前完成北大核心期刊首投，争取 2027-09 至 2028-01 录用。审稿和录用时间不可控。默认每周投入 15–20 小时，单卡 12–24GB，从二维目标检测开始。

## 本周开始

1. 阅读 `reading_matrix.csv` 中 R01、R02；各写 300 字摘要，回答任务、数据、指标、局限四个问题。
2. 跑通一个单模态检测器的训练与评估；在 `experiment_log.csv` 记录代码版本、数据划分、命令、环境、指标和失败原因。尚未确定数据协议前，不比较不同论文的数字。
3. 用 `weekly_tracker.md` 每周复盘；每周固定 2 小时读论文、8–10 小时编码与实验、3–4 小时整理结果、2 小时与导师沟通或写作。

## 实验协议先行

- 主线默认选 RGB＋热红外**行人检测**，从 KAIST 开始；如果导师研究方向是无人机多类别检测，再切换 DroneVehicle，并重建指标和基线表。
- KAIST 行人检测与 DroneVehicle 多类别旋转框检测不是同一评测任务，不能直接比较数值。
- 论文复现前锁定：原始数据来源、标注版本、train/val/test 文件列表、类别、输入尺寸、随机种子、评价代码及指标定义。
- 先用作者权重验证数据与评价流程，再进行训练。保存每次实验配置和原始日志；只在同一协议下比较新方法与基线。
- 代码库外部依赖和预训练权重以作者 README 为准；不要未经核实地将第三方实现标为官方实现。
